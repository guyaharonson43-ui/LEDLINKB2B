# איך הכל עובד: Git, GitHub, אחסון האתר, Netlify ו-Supabase

מדריך קצר שמסביר מה כל כלי עושה בפרויקט LEDLINK, ואיך שינוי עובר מהמחשב שלך לאתר החי `ledlink.co.il`.

---

## תמונת מצב: מה בשימוש בפועל

| כלי | בשימוש? | תפקיד בפרויקט |
|-----|:-------:|----------------|
| **Git** | ✅ כן | שומר את היסטוריית הקוד, כל שינוי נשמר כ"קומיט" |
| **GitHub** | ✅ כן | הריפו `guyaharonson43-ui/LEDLINKB2B`: הגיבוי בענן, Pull Requests, מיזוגים |
| **GitHub Actions** | ✅ כן | בונה את האתר אוטומטית (`.github/workflows/deploy.yml`) |
| **GitHub Pages** | ✅ כן | **זה השרת שמאחסן את האתר החי**, עם הדומיין `ledlink.co.il` (קובץ `CNAME`) |
| **Netlify** | ❌ לא | אין בריפו `netlify.toml` ואין שום הפניה אליו. האתר **לא** רץ על Netlify |
| **Supabase** | ❌ לא | אין בקוד קריאות ל-Supabase. אין מסד נתונים. המוצרים נמצאים בקבצי JS |

> **חשוב:** אם יש לך חשבון Netlify או Supabase שחיברת פעם, הוא לא משפיע על האתר כרגע.
> כל מה שקובע מה מופיע ב-`ledlink.co.il` הוא הענף `main` ב-GitHub.

## 1. Git: היסטוריית השינויים

**מה זה:** תוכנה שרצה על המחשב ושומרת "צילום מצב" של כל הקבצים בכל פעם שמבצעים קומיט. אפשר תמיד לחזור אחורה.

**מושגים:**

| מושג | הסבר |
|------|------|
| **Commit** | שמירה של שינוי עם הודעה שמתארת אותו |
| **Branch (ענף)** | עותק נפרד של הקוד לעבודה על שינוי בלי לגעת באתר החי |
| **`main`** | הענף הראשי. **מה שנמצא בו הוא מה שעולה לאתר** |
| **Push** | שליחת הקומיטים מהמחשב ל-GitHub |
| **Pull** | הורדת השינויים האחרונים מ-GitHub למחשב |
| **Merge** | איחוד ענף עבודה לתוך `main` |

**פקודות בסיסיות:**

```bash
git status                     # מה השתנה ועוד לא נשמר
git pull origin main           # לעדכן את המחשב מהגרסה האחרונה
git checkout -b feat/my-change # לפתוח ענף חדש לשינוי
git add .                      # לסמן את כל השינויים לשמירה
git commit -m "תיאור השינוי"   # לשמור
git push -u origin feat/my-change  # לשלוח ל-GitHub
```

## 2. GitHub: הריפו, ה-Pull Requests והמיזוג

**מה זה:** אתר שמחזיק את עותק ה-Git בענן. בפרויקט הזה הוא גם המקום שבונה ומפרסם את האתר.

**זרימת עבודה רגילה (כמו שעבדנו עד עכשיו, למשל PR #21):**

1. עובדים על ענף נפרד (למשל `feat/profile-renders`)
2. דוחפים אותו ל-GitHub
3. פותחים **Pull Request** (PR) אל `main`
4. GitHub Actions **בונה** את האתר כבדיקה. אם הבנייה נכשלת, רואים ❌ ב-PR ולא ממזגים
5. כשהכל ירוק ✅, לוחצים **Merge**
6. המיזוג ל-`main` מפעיל פרסום אוטומטי לאתר החי

## 3. GitHub Actions + GitHub Pages: איך האתר עולה לאוויר

זה החלק שמחליף את מה ש-Netlify היה עושה. הקובץ `.github/workflows/deploy.yml` מגדיר:

| מתי | מה קורה |
|-----|---------|
| **Pull Request ל-`main`** | בנייה בלבד (בדיקה שלא שבור). **לא** עולה לאתר |
| **Push/Merge ל-`main`** | בנייה + **פרסום לאתר החי** |
| **הפעלה ידנית** (Actions → Run workflow) | בנייה + פרסום |

**שלבי הבנייה:**

1. `npm ci`: התקנת הספריות (Vite, React, Tailwind...)
2. `npm run build`, שמריץ שלושה דברים:
   - `scripts/generate-datasheet-manifest.mjs`: רשימת קבצי ה-PDF
   - `vite build`: בונה את `catalog.html`, `index.html`, `guides.html`, `tools.html` לתיקייה `dist/`
   - `scripts/generate-static.mjs`: מעתיק תמונות וקבצים, מייצר `sitemap.xml`, `robots.txt` ודפי שיתוף ל-WhatsApp
3. מעתיק את `landing.html` ו-`assets/` ל-`dist/`
4. מעלה את `dist/` ל-GitHub Pages

**איפה רואים אם זה הצליח:** בריפו ב-GitHub → לשונית **Actions**. ירוק = עלה, אדום = נכשל (לחיצה עליו מראה את השגיאה).

**הדומיין:** הקובץ `CNAME` מכיל `ledlink.co.il`. ההגדרה ב-GitHub נמצאת ב-Settings → Pages. אצל רשם הדומיין צריכות להיות רשומות DNS שמפנות ל-GitHub Pages. **לא למחוק את `CNAME`**, אחרת הדומיין יתנתק.

**כמה זמן לוקח:** בדרך כלל 1–3 דקות מהמיזוג ועד שהשינוי באתר. אם לא רואים שינוי, כדאי לרענן בלי מטמון (Ctrl+Shift+R).

## 4. Netlify: מה זה ולמה הוא לא בפרויקט

**מה זה:** שירות אחסון לאתרים סטטיים, מתחרה של GitHub Pages. הוא מתחבר לריפו ב-GitHub, בונה ומפרסם בכל push.

**מה הוא נותן שאין ב-GitHub Pages:**
- **Deploy Previews**: קישור זמני לכל PR כדי לראות את השינוי לפני מיזוג
- **Netlify Forms**: קבלת טפסים בלי שרת
- **Functions**: קוד צד-שרת קטן (למשל שליחת מייל)
- הפניות (redirects) וכותרות (headers) דרך `netlify.toml`

**מצב נוכחי:** לא בשימוש. האתר פשוט ולידים מגיעים דרך WhatsApp (`wa.me/972504722550`), אז GitHub Pages מספיק.

**אם תרצה לעבור ל-Netlify בעתיד:**
1. להתחבר ל-Netlify עם GitHub ולבחור את הריפו
2. Build command: `npm run build`, Publish directory: `dist`
3. להעביר את הדומיין `ledlink.co.il` ל-Netlify (DNS)
4. לכבות את GitHub Pages כדי שלא יהיו שני אתרים שמתחרים על אותו דומיין

> ⚠️ לא להפעיל את שניהם יחד על אותו דומיין.

## 5. Supabase: מה זה ולמה הוא לא בפרויקט

**מה זה:** מסד נתונים בענן (PostgreSQL), עם התחברות משתמשים, אחסון קבצים ו-API מוכן.

**מתי הוא רלוונטי:**
- ניהול מוצרים ממסך ניהול, במקום לערוך את קבצי המוצרים
- שמירת לידים/הצעות מחיר מטופס באתר
- אזור לקוחות עם התחברות (מחירון B2B אישי)
- עדכון מלאי או מחירים בלי קומיט

**מצב נוכחי:** לא בשימוש. כל הנתונים סטטיים:

| נתונים | איפה נמצאים |
|--------|-------------|
| מוצרים | `products_data_with_lighting.js` (הקטלוג טוען אותו), ועותקים ב-`products_data.js` ו-`lighting_products.js` |
| דפי מוצר (PDF) | `datasheets_data.js` + תיקיית `datasheets/` |
| תמונות | `product-images/`, `strips/`, `assets/` |

כדי לעדכן מוצר צריך לערוך את הקובץ, לבצע commit ולמזג ל-`main`. האתר מתעדכן אחרי הבנייה.

**אם תוסיף Supabase בעתיד:**
- **מפתח `anon` (ציבורי)** מותר בקוד של האתר, **בתנאי** שהפעלת Row Level Security (RLS) על כל טבלה
- **מפתח `service_role`** לעולם לא בקוד ולא ב-Git. הוא עוקף את כל ההרשאות
- משתני סביבה נשמרים ב-GitHub → Settings → Secrets, לא בקבצים

## 6. סיכום: מה לעשות כשרוצים לשנות משהו באתר

```
עריכה במחשב  →  commit  →  push לענף  →  Pull Request  →  בדיקת build ✅
                                                               ↓
                                     האתר החי מתעדכן  ←  Merge ל-main
```

| רוצה ל... | עושים |
|-----------|-------|
| לראות את האתר מקומית | `npm install` ואז `npm run dev` |
| לבדוק שהבנייה עובדת | `npm run build` ואז `npm run preview` |
| לעדכן מוצר | לערוך `products_data_with_lighting.js` → PR → Merge |
| לבדוק למה האתר לא התעדכן | GitHub → Actions → הריצה האחרונה |
| לחזור לגרסה קודמת | ב-PR הרלוונטי ב-GitHub → **Revert** → Merge |
